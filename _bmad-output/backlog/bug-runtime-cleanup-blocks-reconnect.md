# Повторный Connect разрешён после неудачного удаления runtime

## Description

При отказе удаления конфигурации сессия переходит в Error, но следующий Connect
допускается при оставшемся plaintext runtime. Повторное подключение должно быть
безопасно относительно незавершённой очистки; ошибка не должна теряться.

## Reproduction

Исходная точка: 910c353, Windows, тестовый профиль с синтетическими секретами,
одноразовый каталог данных и управляемый fake child. После создания runtime открыть
его config без разрешения удаления, завершить сессию и дождаться Error. Убедиться,
что файл остался, затем отправить Connect с корректным ID. По исходникам команда
принимается. Это план воспроизведения; фактический прогон ещё не выполнен.
После проверки освободить handle и удалить только собственный тестовый каталог.

## Cause Hypothesis

Завершение worker сообщает об окончании даже после ошибки удаления; обработчик
снимает резерв сессии, а admission следующего подключения проверяет только этот резерв.

## Acceptance Criteria

1. **Незавершённая очистка учитывается при подключении**
   **Given** удаление runtime не удалось и файл существует
   **When** отправлен следующий Connect
   **Then** новый рабочий Xray не запускается до подтверждённого завершения очистки;
   доступна безопасная причина отказа, не содержащая конфигурацию.
2. **Восстановление возможно**
   **Given** препятствие удалению устранено
   **When** выполнено документированное действие восстановления
   **Then** остаток удалён, нормальное подключение снова допустимо; автоматического restart-loop нет.
3. **Проверки покрывают отказ и восстановление**
   **Given** управляемый сценарий отказа
   **When** запускаются regression-проверки
   **Then** подтверждены запрет второго child, сохранение безопасной ошибки, восстановление,
   штатный Disconnect и cancel во время Connecting; тестовые секреты отсутствуют в логах.
4. **Либо изменение не нужно, что доказано**
   **Given** текущий код и описанное воспроизведение
   **When** выполнена проверка
   **Then** требуемое поведение критериев 1–3 подтверждено без изменения продукта;
   команды, результаты и ограничения записаны в Notes. Опровержение гипотезы причины
   само по себе задачу не закрывает.

## Boundaries

Сохранить single writer, sessionID gating, один Wait, exclusive ownership каталога,
startup recovery и запрет удаления ресурсов живого другого экземпляра.

## Notes

- Предложение риска: high — незавершённая очистка оставляет чувствительные параметры на диске; P2 — перезапуск приложения после снятия блокировки даёт recovery-путь.
- Open question: способ восстановления выбирается при реализации; безопасный результат задан критериями, механизм не предписан.
- Дополнительная проверка высокого риска: два экземпляра приложения и отказ удаления не приводят к очистке живого каталога другого владельца.

- Decision: 2026-11-01 — пользователь утвердил план и поручил автономное выполнение; критерии и предложенные риски приняты. Доступность сред подтверждается фактически перед стартом.
