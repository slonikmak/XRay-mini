# Как завершать сессию при ошибке остановки дочернего процесса

## Description

Установить наблюдаемое поведение при ошибке Kill и незавершившемся Wait и определить
безопасный следующий шаг. На ответ ждут системные проверки 7 и 8. Синтетический
отказ API не считать доказательством реального отказа Windows.

## Approach

1. Воспроизвести управление fake child, который возвращает ошибку остановки и ждёт
   отдельный сигнал завершения; гарантировать release в teardown.
2. Сопоставить с нативным process/job lifecycle и проверить варианты без второго Wait,
   утечки handle или ложного Disconnected. Объём — один сценарий отказа и один короткий
   прототип; полноценная переработка supervisor не входит в spike.
3. Записать вывод и доступные варианты в `_bmad-output/backlog/evidence/child-termination-failure.md`.
   При необходимом изменении сформулировать отдельную bug/story с критериями; она должна
   предшествовать 7/8, если влияет на их приёмку.

## Acceptance Criteria

1. **Поведение отказа установлено** — Verify: отчёт различает fake failure, нативный
   процесс и кодовую гипотезу; записаны команды, среда и cleanup сценария.
2. **Варианты оценены по обязательным гарантиям** — Verify: сравнение сохранения ownership,
   конечности shutdown, once-only Wait, job containment и честного статуса; вывод не
   обходит требования таймером, оставляющим child живым.
3. **Ответ доступен следующим задачам** — Verify: записано доказанное «изменение не нужно»
   либо предложение исправления с воспроизведением и критериями. Новая работа не
   объявлена выполненной этим исследованием.

## Notes

- Предложение риска: high — неверное решение может оставить работающий proxy после завершения приложения.
- Зависимость от 2: общий shutdown-контракт, результаты callback-исправления учитываются до изменения supervisor.
- Дополнительная проверка высокого риска: отмена одновременно с поздним успешным созданием child не теряет владельца процесса.
