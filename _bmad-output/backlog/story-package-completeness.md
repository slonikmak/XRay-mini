# Комплектность поставки проверяется до передачи пользователю

## Description

Проверять полный комплект GUI, pinned runtime и обязательных notices при подготовке
поставки. Текущая поздняя ошибка копирования notices завершает packaging с ошибкой,
но может оставить изменённую неполную папку; она не должна считаться готовой поставкой.

## Requirements

1. **Полный комплект подтверждён**
   **Given** успешно подготовленная поставка
   **When** выполнена документированная проверка готовности
   **Then** доступны GUI, ожидаемый runtime с верным digest и требуемые license/notice;
   результат относится к конкретному комплекту файлов.
2. **Частичный комплект отклонён**
   **Given** отсутствует/повреждён runtime или не записан license/notice
   **When** выполняется packaging либо проверка готовности после его сбоя
   **Then** частичный комплект не получает успешного результата готовности;
   причина доступна и повторный запуск после устранения отказа даёт полный комплект.
3. **Проверки не требуют загрузки/запуска неизвестного core**
   **Given** синтетический архив и управляемые ошибки записи в собственном temp-каталоге
   **When** выполняются regression-проверки
   **Then** покрыты success и отказ каждого ancillary write; результат не подменяет
   проверку официальных pins реальной поставки.

## Boundaries

Сохранить official source, archive/executable pins, runtime validation и лицензионные
обязательства. Installer, подпись и автообновление не добавлять.

## Notes

- Предложение риска: medium — передача неполного комплекта делает поставку непригодной.
- Не требуется конкретная стратегия atomic replacement: готовность полного комплекта должна быть проверяема независимо от устройства packaging.

- Decision: 2026-11-01 — пользователь утвердил план и поручил автономное выполнение; критерии и предложенные риски приняты. Доступность сред подтверждается фактически перед стартом.
