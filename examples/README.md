# Примеры без секретов

Замените все значения REPLACE_* и домен `server.example.invalid` данными вашего сервера. Эти файлы намеренно не являются готовыми соединениями. Не отправляйте заполненные конфиги в публичный репозиторий.

Параметры `flow`, транспорт, путь XHTTP, SNI, fingerprint, publicKey и shortId должны совпадать с сервером. Не добавляйте Vision flow к XHTTP по аналогии с RAW: используйте выданный сервером конфиг.

## Контракт импорта v0.2

Три шаблона покрывают RAW + REALITY, XHTTP + REALITY и XHTTP + TLS. Они не являются свидетельством реального e2e: необходим ваш отдельно подготовленный тестовый сервер.

Импорт принимает ровно один VLESS outbound с объектом `streamSettings`. Предварительный просмотр перечисляет отброшенные секции. Приложение создаёт собственные loopback inbounds и маршрут к единственному outbound `selected-vless`; исходные routing, DNS, policy, log и остальные outbounds не переносятся. Произвольные transport-параметры не редактируются UI.

Поддерживается самостоятельный клиентский профиль RAW/TCP или XHTTP/splithttp. Chaining (`proxySettings`, `dialerProxy`), `sockopt`, `sendThrough`, ссылки на файлы сертификатов/ключей, key logging, reverse, finalmask и отдельный `downloadSettings` намеренно отклоняются: такой профиль зависит от неподдерживаемых ресурсов или второй транспортной конфигурации. Дубликаты JSON-ключей (включая разные регистры) также отклоняются. Параметры принятого транспорта и безопасности сохраняются; окончательную проверку синтаксиса выполняет закреплённый Xray до запуска.

Основание для ограничений: [структура outbound](https://xtls.github.io/en/config/outbound.html) и [структура transport](https://xtls.github.io/en/config/transport.html).
